# v0.2.6 REALITY 默认目标与随机端口验证

## REALITY 连接问题

同一入口和出口下，Shadowsocks 能完成代理请求，默认 VLESS + REALITY + Vision 连接在握手阶段失败。已核对面板记录、实际运行配置和分享链接中的 UUID、flow、公钥、私钥推导结果及 Short ID 一致；外部客户端和入口机器上的回环客户端均能复现。

在入口机器上启动独立、仅监听回环地址的临时服务端和客户端，保留相同转发出口，仅比较核心版本与目标站：

| 服务端核心 | REALITY 目标 | 实际 HTTPS 代理请求 |
|---|---|---|
| v26.6.27 | www.microsoft.com:443 | 失败 |
| v26.6.27 | www.cloudflare.com:443 | 成功 |
| v26.10.31 | www.microsoft.com:443 | 成功 |
| v26.10.31 | www.cloudflare.com:443 | 成功 |

结果定位到旧核心与当时 Microsoft 目标站握手数据的兼容性。普通 TLS 回落连接可协商 TLS 1.3 和 h2，仍不能证明认证 REALITY 握手成功。临时诊断进程和目录已清理。

新建转发的默认 SNI/目标改为 `www.cloudflare.com` / `www.cloudflare.com:443`，与后端既有补全值一致。目标站和网络条件可能随时间变化；上述结果记录本次实测组合。

## 已有规则的线上验收

在备份规则与部署版本、确认节点无进行中任务后，仅将已定位规则的目标站和 SNI 改为 Cloudflare，再通过面板应用至专用中转服务。核心版本、监听端口、UUID、密钥、Short ID、flow、入口与出口选择均保留。

- 外部官方 Xray v26.10.31 客户端使用更新后的分享链接，VLESS 代理请求成功。
- 外部官方 Xray v1.8.24 客户端使用更新后的分享链接，VLESS 代理请求成功。
- Shadowsocks 控制请求成功，规则记录保持不变。
- 三次请求得到相同出口 IP。
- 原有 x-ui/Xray 服务状态、进程及启动标识、配置 SHA-256 在操作前后一致。

应用只重载面板管理的独立中转服务。同一专用服务上的连接可能短暂重连。未修改原有代理服务或全局网络配置。诊断客户端使用认证回环 SOCKS、显式代理路由和默认拒绝出口，禁止代理失败后直连；只终止本次诊断创建的进程。

已有客户端需要重新复制面板中的分享链接或刷新订阅，以同步新的 SNI。安装补丁本身不会批量修改其他已有规则。

## 五位数随机端口

新建转发从 **10000–65535** 均匀随机选择端口，使用 `crypto.getRandomValues` 和拒绝采样。随机时避开同一入口已保存转发的端口，包含停用规则；“随机端口”按钮同时排除当前值。

新建草稿自动选择端口后，切换入口会按新入口重新选择。手动输入及编辑已有规则会保留端口；手动输入仍允许 1–65535。服务器上其他程序的端口占用由应用节点时的既有检查处理。

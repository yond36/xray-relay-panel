# v0.1.0 历史验证摘要

验证日期：2026-11-07。面板版本：`0.1.0`；固定 Xray-core：`v26.10.31`。本文件整理既有验收结果，供公开发布查阅；未在整理文档时重新运行测试。

## 范围与结论

Linux amd64 上的 SSH 远程节点和面板本机节点均通过配置应用及出口检测。独立 Windows Xray 客户端通过公网 VLESS-REALITY 入口和 VLESS-REALITY 上游完成 IPv4 请求。故障上游没有触发直连回退，专用节点启动失败后恢复上一可用修订。既有 x-ui / Xray 服务隔离检查通过。

## 构建与配置检查

| 检查 | 历史结果 |
| --- | --- |
| `go test ./...` | 通过：API、认证、加密、存储、协议配置及执行器测试 |
| `go vet ./...` | 通过 |
| TypeScript + Vite 正式构建 | 通过 |
| 当时的 npm 依赖审计 | 未报告已知漏洞；不代表当前安全状态 |
| Windows amd64 构建 | 通过，并用于 SSH 管理检查 |
| Linux amd64 构建与安装 | 通过 |
| Linux arm64 交叉构建 | 通过；未做 ARM64 实机运行测试 |
| 安装脚本语法检查 | 通过 |
| Xray 配置矩阵 | 22 组入口及分享链接重导入，共 44 次核心配置检查通过 |

配置矩阵覆盖 VLESS-REALITY，VLESS/VMess/Trojan 的 RAW、WS、gRPC、XHTTP 与 TLS 组合，以及 Shadowsocks AEAD/2022、SOCKS、HTTP 的相应合法入口。矩阵确认固定核心接受这些配置；实际公网转发仅覆盖 VLESS-REALITY 入口和 VLESS-REALITY 上游。

当时的构建工具为 Go 1.27.3、Node.js 22.22.3、npm 10.9.8、Vite 6.4.5。

## 转发、恢复与隔离

| 场景 | 历史结果 |
| --- | --- |
| Windows 面板经 SSH 管理 Linux 节点 | 配置应用和 IPv4 出口检测通过 |
| Linux 面板以普通系统账户管理本机节点 | 配置应用和 IPv4 出口检测通过 |
| 独立客户端经公网入口访问上游 | IPv4 完整链路通过 |
| IPv6 出口 | 检测超时，作为独立错误显示 |
| 不可用回环 SOCKS 上游 | 探测失败，没有直连降级 |
| 配置合法但运行时无法绑定监听地址 | 启动失败，恢复前一组二进制与配置，专用服务恢复 active |
| 检测端口与其他监听冲突 | 检测改用独立、按需创建和清理的进程后，通过故障回归 |
| SSH 管理程序上传与取消 | 有限并发上传及取消中断检查通过 |
| 既有 x-ui / Xray 隔离 | 进程启动状态、程序与配置完整性、监听状态在测试前后保持一致 |

测试没有修改其他服务及全局防火墙或 sysctl。单次网络请求中曾出现 TLS 超时后重试成功；本次检查不是吞吐、延迟或持续稳定性基准。

# v0.2.5 默认转发请求修复与验证

新建转发表单包含内部草稿时间字段 `created_at: ""`、`updated_at: ""`。旧提交逻辑展开整个草稿，导致后端将空字符串解码到 `time.Time` 时失败，返回“JSON 请求格式或字段无效”。

本版将默认草稿和提交构造集中在 `web/src/relay-form.ts`，新建与编辑共同使用；请求省略两个服务端维护的时间字段，保留已有协议、安全层、路由、公网地址与凭证处理逻辑。

## 回归验证

- 前端 20 项测试通过，其中 6 项覆盖实际默认草稿序列化、时间字段省略、编辑身份与禁用状态、凭证保留、公网地址继承，以及协议切换时的字段清理。
- 前后端共用 `tests/fixtures/default-relay-request.json`。前端生成结果与该契约一致，后端替换资源 ID 后使用同一 JSON 发起请求。
- 默认 VLESS + REALITY + Vision 请求创建返回 HTTP 201，服务端生成记录 ID、时间、UUID 与 REALITY 凭证。
- 编辑返回 HTTP 200，省略时间字段仍保留原创建时间和凭证，并能保存 `enabled: false`。
- 任一或两个空时间字符串、未知字段仍被严格解析器拒绝；未放宽后端校验。
- 保存仅标记待应用，未产生部署任务或调用应用/服务操作。
- 完整 `go test ./...`、`go vet ./...`、TypeScript/Vite 及 Windows 程序构建通过。

上述写入测试使用隔离数据和测试运行时。线上仅匿名读取了公开版本接口，未登录账号、修改线上配置或应用到节点。本次未执行浏览器 GUI 复测，使用表单构造与真实 API 处理器的共享契约回归验证请求。

## 升级提示

安装 v0.2.5 后刷新浏览器页面，必要时使用 Ctrl+F5，以加载新版表单。仅更新服务端进程而继续使用旧页面中的表单代码，仍可能提交旧时间字段。

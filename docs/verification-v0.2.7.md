# v0.2.7 已应用转发直接删除

## 行为与原问题

原删除处理器同时保护当前部署与 Previous 回滚快照中的规则引用。因此禁用并应用一次后，旧部署仍在 Previous 中，继续删除仍被拒绝。旧界面对所有规则统一显示多步操作提示。

本版保留同一删除接口，点击“删除”并确认后自动完成配置更新和规则删除：

- 没有部署引用的规则保留即时 HTTP 200 删除响应。
- 当前部署或回滚引用的规则返回 HTTP 202 及 `delete-relay` 任务，任务通过可选 `relay_id` 持久关联目标。
- 后台应用排除目标规则后的入口配置，处理节点侧回滚链接；确认成功后，在一个数据库事务中提交部署版本、快照、删除记录及任务成功。
- 删除会应用该入口其他待生效配置，可能使同一专用节点上的连接短暂重连。
- 删除最后一条规则后，应用无入口、默认拒绝的配置。

## 失败与回滚边界

远端操作之前持久化删除意图。运行时失败、取消、进程中断或远端成功但数据库提交失败时，保留规则和凭据，任务不会被报告为成功；未完成协调的意图阻止使用旧快照回滚。直接重试删除或显式应用当前配置，可以完成协调。错误时节点可能已完成部分更新，保留记录不代表运行配置一定未变化。

回滚在入队和实际执行前均复核最新快照，避免删除运行期间已排入的旧回滚任务恢复目标规则。成功删除后，只有不含目标的旧当前部署才能保留为回滚快照。

节点 helper 在同一次应用操作和节点锁内检查候选配置不含目标标签。旧 current 实际包含目标时，清除固定 previous 链接；旧 current 安全时用其覆盖 previous。未链接的历史备份目录按既有策略保留，不作为公开回滚入口。所有服务及路径继续限定于面板自己的独立节点；不扩展原有 x-ui/Xray 的管理范围。

## 界面验收限制

使用独立数据目录、真实 API/认证/存储与受控运行时准备了 3 个合成入口、4 条转发、2 个成功的合成应用任务。准备阶段没有触发删除，也没有连接真实业务节点。

正式 GUI 验收时，内置浏览器可以加载并读取 v0.2.7 登录页面，但首次截图返回 `browser screenshot surface preparation timed out after 3000ms`，未产生可查看的截图。删除成功、删除中、失败保留和最后一条删除的 GUI 测试点均记为未完成，未计为通过。已停止 GUI 测试，未通过脚本点击、改路由、其他浏览器或 API 替代 GUI 测试；隔离面板进程和测试标签页已关闭。当前浏览器接口没有提供控制台日志读取能力。

## 验证范围与升级

实际 Linux 核心验收只启动独立的空配置进程；未删除生产转发或应用新的业务配置。账户、连接信息、原始日志与运维记录保留在私有目录，不进入公开源码或发行包。

升级至 v0.2.7 后刷新浏览器页面，点击转发的“删除”并确认即可。节点暂时不可达时会保留记录并报告任务失败，恢复连通后可直接重试。
